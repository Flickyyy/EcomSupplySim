1 Описание программы

1.1 Архитектура и модули

Программа реализована на Go 1.23 с разделением на три пакета. Каждый блок модели (Б1–Б6) соответствует функции в коде.

internal/rng
internal/rng/rng.go · 127 строк
ГПСЧ xoshiro256** и 7 процедур генерации распределений. Полностью самописный — без math/rand.
internal/sim
internal/sim/sim.go · ~490 строк
Движок: Config, Order, Stats, DaySnapshot, Engine. 6 блоков (Б1–Б6), 4 сценария. Каждый день — независимый повтор с посуточным снимком метрик.
cmd/sim
cmd/sim/main.go · ~200 строк
CLI: флаги -scenario, -seed, -orders, -daily. Выводит агрегированные метрики + таблицу вариации по дням. Опционально экспортирует посуточный JSON.
docs/
docs/lab1/report.html · docs/lab2/report.html
Отчёты ПР №1 (модель) и ПР №2 (программа).

1.2 ГПСЧ — xoshiro256**

Генератор xoshiro256** (Blackman & Vigna, 2018). Период 2256−1, состояние 256 бит (4×uint64). Seeding через SplitMix64.

2 Работа программы

go run ./cmd/sim [flags]

Флаги:
  -scenario    default | peak | chaos | understaffed   (default: "default")
  -seed        uint64 seed для ГПСЧ                    (default: 42)
  -orders      минимальное число заказов                (default: 1 000 000)
  -daily FILE  записать посуточный JSON в файл

Каждый виртуальный день — 1440 минут модельного времени, независимый повтор эксперимента. После каждого дня записывается DaySnapshot с метриками этого дня. Мастер-ГПСЧ порождает уникальный seed для каждого дня.

Default — 5 курьеров

Базовый сценарий — курьерский пул ограничен. Загрузка 80.6%, значительная часть заказов возвращается (22.7% restocked + 7.5% disposed). Ср. время доставки >100 мин.

Peak (λ×2.5, 25 курьеров)

Нагрузка ×2.5, но 25 курьеров. Результаты резко лучше: 84.2% доставлено, ср. время 42.5 мин, загрузка сборки 36.2%. Курьерский пул решает проблему.

Chaos (λbreak×5, σtr×2)

Поломки ×5 + пробки ×2 при 5 курьерах. Загрузка 87.7%, наихудший SLA breach 9.2%. Express SLA breach 65.7% — критично.

Understaffed (8 курьеров)

+3 курьера (8 vs 5) — уже заметное улучшение: 82.6% доставлено (vs 67.6%), ср. время 49.8 мин (vs 100.6). Загрузка курьеров 48.3% — комфортная зона.

4 Анализ по дням (многократные независимые повторы)

Каждый смоделированный день — это независимый повтор эксперимента со своим seed ГПСЧ, сброшенным состоянием ресурсов и инвентарём. После каждого дня фиксируется DaySnapshot: количество заказов, доля доставленных, среднее время доставки, % SLA breach, загрузка ресурсов.

Загрузка курьеров (%) — все сценарии

4.3 Сходимость средних

Графики наглядно показывают, что посуточные средние стабильны и стационарны: нет тренда (ни роста, ни убывания) — все метрики колеблются вокруг своего среднего. Это подтверждает, что:

  • Каждый день — действительно независимый повтор
  • 1 000 000 заказов (~6 700 дней) достаточно для репрезентативной оценки
  • Финальные средние — надёжные оценки истинных значений
Доверительный интервал (Default, Delivered %): mean=68.0%, σ=13.0%, N=6708 ⇒ SE=0.16% ⇒ 95% CI = [67.7%, 68.3%]. Высокая точность оценки благодаря большому числу повторов.
