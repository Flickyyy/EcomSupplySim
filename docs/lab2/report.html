1 Описание программы

1.1 Архитектура и модули

Программа реализована на Go 1.23 с разделением на три модуля в соответствии с функциональными блоками модели из ПР №1. Каждый блок модели (Б1–Б6) соответствует конкретной функции или набору функций в коде.

internal/rng/rng.go · 127 строк
Генератор псевдослучайных чисел xoshiro256** и 7 процедур генерации распределений. Полностью самописный — без math/rand. Единственная зависимость: math (для Log, Sqrt, Cos, Exp).
internal/sim
internal/sim/sim.go · 456 строк
Ядро моделирования: типы Config, Order, Stats, движок Engine. Реализованы все 6 функциональных блоков (Б1–Б6) и 4 сценария конфигурации. С каждым заказом последовательно проходит по цепочке: генерация → диспетчеризация → сборка → доставка → клиент → возврат.

1.2 Генератор случайных чисел — xoshiro256**

Реализован генератор xoshiro256** (Blackman & Vigna, 2018). Это high-quality all-purpose PRNG с периодом 2256−1 и состоянием 256 бит (4×uint64).

Почему xoshiro256**: Быстрый (~1 нс/вызов), отлично проходит BigCrush тесты TestU01, не требует внешних зависимостей. Подходит для имитационного моделирования с большим количеством испытаний. Отличается от стандартного math/rand (PCG) алгоритмом — нет совпадений с другими работами.

Алгоритм ГПСЧ

// Seeding: SplitMix64 разворачивает 1 uint64 seed в 4-word state
func splitMix64(state *uint64) uint64 {
    *state += 0x9e3779b97f4a7c15       // golden ratio
    z := *state
    z = (z ^ (z >> 30)) * 0xbf58476d1ce4e5b9
    z = (z ^ (z >> 27)) * 0x94d049bb133111eb
    return z ^ (z >> 31)
}

// xoshiro256** core: scrambler = rotl(s1*5, 7) * 9
func (r *Xoshiro256ss) Uint64() uint64 {
    result := rotl(r.s1*5, 7) * 9      // output scrambler
    t := r.s1 << 17                    // mix
    r.s2 ^= r.s0; r.s3 ^= r.s1        // state update
    r.s1 ^= r.s2; r.s0 ^= r.s3
    r.s2 ^= t;    r.s3 = rotl(r.s3, 45)
    return result
}

// Uniform [0, 1): верхние 53 бита / 2^53 — полная точность float64
func (r *Xoshiro256ss) Float64() float64 {
    return float64(r.Uint64()>>11) / (1 << 53)
}

1.3 Генерация произвольных распределений

Все 7 распределений генерируются из равномерного U[0,1) по процедурам, описанным на лекции 2:

РаспределениеМетод генерацииФормула / алгоритмПрименение в модели
Exp(λ) Метод обратной функции X = −ln(1−U) / λ Интервалы заказов (Б1), время ремонта (Б4), инспекция (Б6)
N(μ, σ) Преобразование Бокса–Мюллера Z = √(−2·ln(1−U1)) · cos(2πU2)
X = μ + σ·Z		 Время сборки заказа (Б3)
LN(μ, σ) Через нормальное X = exp(N(μ, σ)) Коэффициент трафика (Б4)
Bern(p) Прямое сравнение X = (U < p) Брак (Б3), отсутствие клиента (Б5), возврат (Б5), утилизация (Б6)
U(a, b) Линейное масштабирование X = a + U·(b−a) Ожидание повторной доставки (Б5), расстояние
Uint(a, b) Дискретизация X = a + ⌊U·(b−a+1)⌋ Число позиций в заказе (Б3)
Pois(λ) Алгоритм Кнута Подсчёт: k++; p*=U; пока p>e−λ Вспомогательный (для расширений)

1.4 Функциональные блоки модели в коде

Каждый из 6 блоков модели из ПР №1 реализован как часть метода Engine.SimulateDay() и Engine.processOrder():

БлокРаспределенияРеализация в Go
Б1 OrderGenerator Exp(λ(t)), Bern (приоритет) SimulateDay(): цикл генерации заказов. λ(t) переключается по часам суток через lambdaBase(hour). Приоритет: 5% express / 20% same-day / 75% standard.
Б2 Dispatcher — (детерминированный) processOrder(): перебор магазинов, выбор слота с минимальным временем готовности + проверка stock>0. Нет товара → CANCELLED.
Б3 Store Assembly N(15,4), Uint(1,5), Bern(0.02) Время сборки: NormalPositive(15,4,1) × w, где w = 1+0.05·(nItems−1). Дефект → Б6 (инспекция, возможная утилизация).
Б4 Courier Delivery LN(0,0.35), Exp(1/30), U(0.5,8) Выбор свободного курьера (min courFree). Время: (dist/speed)×60×LN. Поломка: Bern(1−e−λ·t/1440) → +Exp(30мин).
Б5 Customer Bern(0.15), Bern(pret), U(60,240) До 2 попыток. pret = 0.08·(1+0.5·delayRatio)·βSLA. Отказ → Б6. 2 неудачи → CANCELLED.
Б6 Return Logistics LN(0,0.35), Exp(1/10), Bern(0.25) Обратная доставка + инспекция. Критический брак (25%) → DISPOSED, иначе → RESTOCKED (инвентарь +1).

2 Работа программы

2.1 Параметры запуска

go run ./cmd/sim [flags]

Флаги:
  -scenario  default | peak | chaos | understaffed    (default: "default")
  -seed      uint64 seed для ГПСЧ                     (default: 42)
  -orders    минимальное число заказов                 (default: 1 000 000)

Модель запускается посуточно: каждый виртуальный «день» — 1440 минут модельного времени. Дни прогоняются последовательно до набора заданного количества заказов. Мастер-ГПСЧ порождает уникальный seed для каждого дня — обеспечивает воспроизводимость всех результатов при повторном запуске с тем же seed.

Default — Базовый

Система справляется легко: загрузка курьеров 25.7%, сборки 14.2%. Резерв мощности значительный. SLA-нарушения минимальны (1.5%, почти все — express).

Peak (λ×2.5, 25 курьеров)

Нагрузка ×2.5, но добавлены 10 курьеров. Загрузка курьеров выросла до 39.2%, сборки — до 36.2%. Система держит удар. Ср. время доставки практически не изменилось (+1.4 мин).

Chaos (λbreak×5, σtr×2)

Массовые поломки и пробки. Ср. время доставки +2.1 мин, время возвратов +1.9 мин. Express SLA breach 18% (vs 14.8% default). Система деградирует мягко.

Understaffed (8 курьеров)

Курьеров почти вдвое меньше. Их загрузка 48.3%, ср. время +8.7 мин. Express SLA breach 24.1% — критично. RESTOCKED растёт до 11.4% (больше возвратов из-за задержек).
