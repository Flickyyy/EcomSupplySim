1 Описание модели и цель оптимизации

Объект моделирования: логистическая система e-commerce доставки с возвратами. Базовая имитационная модель разработана в ПР1-3 и включает генерацию заказов, сборку, доставку, клиентское взаимодействие, возврат и утилизацию.

Переменные оптимизации (decision variables)

  • NCouriers — число курьеров, диапазон 4..24, шаг 2.
  • NStores — число магазинов/складов, диапазон 3..6.
  • SlotsPerStore — слоты сборки на магазин, диапазон 2..5.

Выходные метрики (KPI)

  • Service: Delivered %, SLA breach %, Avg delivery time.
  • Resource: Courier util %, Assembly util %.
  • Loss: Cancelled %, Disposed %.
  • Economic: интегральная стоимость (целевая функция).

2 Целевая функция и ограничения

Оптимизационная постановка: минимизация ежедневных затрат при выполнении SLA/качества сервиса.

TotalCost = 2200*NCouriers + 5000*NStores + 700*(NStores*SlotsPerStore) + 1800*SLA_breach_pct + 1000*Cancelled_pct + 2400*Disposed_pct

3 План экспериментов и воспроизводимость

Design of Experiments

Использован полный перебор по решетке параметров: 11 значений NCouriers × 4 значения NStores × 4 значения SlotsPerStore = 176 конфигураций. Каждая конфигурация оценивается на трех уровнях нагрузки.

Случай нагрузкиLambdaMultВес в интегральной оценке

Правила воспроизводимости

  • Фиксированный базовый seed: 20260319.
  • Для каждой точки решетки и сценария используется детерминированный derived-seed.
  • На каждую оценку: не менее 60 000 заказов.
  • Команда запуска: go build -o opt ./cmd/opt && ./opt > docs/lab4/data.json.

4 Результаты оптимизации

Использованные методы оптимизации

  • Полный перебор (grid search): вычисление целевой функции для всех 176 конфигураций в заданных диапазонах.
  • Локальный поиск (hill climbing): дополнительная проверка улучшения решения из базовой точки (default) по соседним конфигурациям.
  • Выбор финального решения: минимум objective среди feasible-конфигураций, удовлетворяющих всем ограничениям.
